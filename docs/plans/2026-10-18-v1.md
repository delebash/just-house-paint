## 2 · The engines (server package, `server/src/`)

| Piece | Choice | Standard |

## 3 · Data (§16 of the standard)

Tables (migration 1, besides the template's `settings`): `houses` (id, name, file names, width,
height, times) · `parts` (house, key, label key, paintable, mask file, area, score, source auto/edited)
· `designs` (id, house, name, times) · `design_colors` (design, part, paint) · `brands` (key, label,
source, enabled, loaded count, loaded at, last error) · `paints` (id `<brand>:<code>`, brand, code,
name, hex, r/g/b, Lab, LRV, exterior/interior, family, collection, source) · `paint_coordinating`
(paint, other) · `renders` (AI photos: id, house, design, file, ΔE, engine, time). Files under
`<dataDir>/houses/<id>/` (original, display copy, thumbnail, `masks/<part>.png`, `renders/`) and the
models under `<dataDir>/models/`. Settings rows: the parts recipe, the detection thresholds, the tint
settings, the AI photo prompt templates.

## 4 · The API (`/v1/*`, every body a schema in `server/src/schemas/`)

Houses: `GET/POST /v1/houses` (multipart upload), `GET/PATCH/DELETE /v1/houses/:id`,
`GET /v1/houses/:id/image?size=display|thumb|original`. Parts: `POST /v1/houses/:id/find-parts`
(starts the job), `GET /v1/jobs/:id`, `DELETE /v1/jobs/:id`, `GET /v1/houses/:id/parts`,
`GET /v1/houses/:id/parts/:key/mask`, `PUT …/mask` (a touched-up mask), `POST …/tap`. Designs:
`GET/POST /v1/houses/:id/designs`, `PATCH/DELETE /v1/designs/:id`. Paints: `GET /v1/brands`,
`POST /v1/brands/:key/load`, `DELETE /v1/brands/:key`, `POST /v1/paints/import`, `GET /v1/paints`
(search), `GET /v1/paints/:id`. Schemes: `POST /v1/schemes/harmony`, `GET /v1/paints/:id/coordinating`,
`POST /v1/schemes/ai` (the AI feature `schemes.suggest`). AI photo: `GET /v1/aiphoto/status`,
`POST /v1/aiphoto/install`, `POST /v1/houses/:id/aiphoto`. Models: `GET /v1/segment/status`,
`POST /v1/segment/install`.

## 5 · The screens (§17 of the standard)

| Route | Screen | Built from |
|---|---|---|
| `/` | Your houses — a card grid of photos, "Add a photo", the empty state | `QCard` + `QImg`, `QFile`, the kit's `EmptyState` |
| `/house/:id` | **The visualizer** — the photo with the paint on it; tools (before/after slider, outlines, zoom, brush/eraser size, export, AI photo); a side panel with tabs Parts · Colors · Schemes · Designs | the canvas stage on **Konva** (`konva` + `vue-konva`, MIT — konvajs.org) for layers, zoom/pan and the brush; `QTabs`, `QVirtualScroll` for swatches, `QSlider`, the kit's controls |
| `/colors` | Paint colors — brands, load/import, browse | `UiTable`, the kit's controls |
| `/ai`, `/settings/:section?`, `/offline`, help | the template's | — |

The tint runs in the renderer on the display-size photo (the ratio tint in linear light, §9: lit ΔE
0.33–0.64), recomputed only for the part that changed; the export repeats it at full size. Canvas 2D
`ImageData` (MDN) — the browser's standard API. The algorithm is ours, chosen by measurement (§9).
Attacked: (a) "tint on the server" — every color click would round-trip a 12 MP image; the
browser does a 3 MP display copy in tens of milliseconds. (b) "WebGL shader" — faster, but Canvas 2D
is fast enough at display size and has no context-loss handling to get wrong; revisit if a test
shows lag. (c) "hand-draw the brush on raw canvases" — Konva is the vetted library for exactly this.
